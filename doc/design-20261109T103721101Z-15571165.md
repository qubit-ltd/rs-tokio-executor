## 方案与取舍

采用局部修复：改一个依赖版本要求、两处 Rustdoc URL，添加小型契约测试。保留 path 依赖供本地开发，隔离消费者验证时使用临时副本移除该 path，让 Cargo 真正解析 registry 的最低依赖版本。

不采用删除 CancellableTaskHandle 实现来兼容 0.9.0：会移除既有泛型取消能力并影响调用方。不升级到其他 minor，也不引入通用依赖矩阵平台或文档生成框架：这些均超出本轮目标。

### RTE-001

将 Cargo.toml 恢复为 `qubit-executor = { version = "^0.9.1", path = "../rs-executor" }`，保留其他依赖不变。新增 tests/dependency_contract_tests.rs，使用现有 toml、semver dev-dependencies，验证依赖要求排除 0.9.0、接受 0.9.1。

静态契约检查不能替代编译验证。另在仓库外创建一次性消费者，复制当前 crate 的 Cargo.toml、src、README.md 和 LICENSE，移除副本的 rs-executor path；消费者精确依赖 `qubit-executor = "=0.9.1"` 并 path 依赖这个副本。编译使用真实 CancellableTaskHandle 泛型约束的程序，确认源码能使用声明的最低依赖版本。registry 版本不可获取时记录阻断，不能以本地 0.9.1 path 编译替代此结论。

### RTE-002

两处 main URL 改为 `https://github.com/qubit-ltd/rs-tokio-executor/blob/v0.12.0/doc/user_guide.md#runtime-lifetime-and-driver-progress`。在现有 tests/readme_tests.rs 增加发布链接契约：按 Cargo.toml 当前版本构造预期 URL，确认两处 IO 引用均固定发布版本，且 src 下 Rustdoc 不再引用本仓库 blob/main/doc/。测试检查语义和版本来源，不检查中文措辞。

不将本轮发现描述为链接失效，也不承诺远端标签已存在。发布时应确认标签与文档随该版本交付；cargo doc 本身不会验证 HTTP 链接可达性。

## 兼容性与迁移

无公共 API、执行行为、并发协议或文档语言结构变化。依赖下限收紧仅排除已不兼容的 0.9.0。受影响的是锁定该版本的下游，需允许 Cargo 将 qubit-executor 更新到至少 0.9.1；若应用写有精确 =0.9.0 约束，应先调整该约束。已使用 0.9.1 的本地调用方无需源码迁移。
